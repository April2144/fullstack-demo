二、核心问题：浏览器不肯重新下载

静态资源响应头通常带 Cache-Control: max-age=31536000（一年）。 好处是第二次打开飞快；坏处是你改了 CSS，用户看到的还是旧的。

解法不是缩短缓存时间（那等于放弃缓存）， 而是改 URL：URL 一变，浏览器就认为这是一个全新文件。

<!-- 改之前 -->
<link rel="stylesheet" href="style.css">

<!-- 改之后：加版本号，缓存立刻失效 -->
<link rel="stylesheet" href="style.css?v=20261021">

点一下试试

当前加载：theme-v1.css?v=1

这块颜色来自 theme-v*.css

打开开发者工具 → Network → 勾选 Disable cache 关掉，再点按钮： 能看到 theme-v2.css?v=2 是一次新的请求（状态 200，不是 304 或 memory cache）。

三、版本号的三种写法

写法 例子 适用
时间戳 ?v=202610211530 手动更新，最简单，但每次都要改
内容哈希 ?v=a3f9c1 构建工具自动生成，内容不变哈希不变，缓存命中率最高
发布版本号 ?v=1.4.2 整站一次发布，配置简单，粒度较粗

本仓库不引入构建工具，所以用「手动版本号」；用 Vite / Webpack 的项目会自动生成内容哈希。

四、Nginx 里的缓存策略

原则：带哈希的静态资源长缓存，HTML 永不缓存。

# HTML：不缓存，保证用户总能拿到最新的资源引用
location ~* \.html$ {
    add_header Cache-Control "no-cache";
}

# 带版本号的静态资源：缓存一年
location ~* \.(css|js|woff2|png|jpg|svg)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

immutable 的意思是「这个 URL 的内容永不改变」，浏览器连条件请求都不会发，省一次往返。

前提：URL 里必须带版本号或哈希。否则改了文件、URL 没变，用户一年都看不到新版。
