一、构建工具到底做了什么

「构建」听起来玄，拆开看只有四个动作。本页的脚本只做前两个 —— 足够让你看清原理， 剩下的交给真实工具。

动作 具体在干什么 本页脚本
合并 多个文件按依赖顺序拼成一个，减少请求数 ✅ utils.js + app.js → 一个
压缩 删注释、删缩进、合并空白，不改逻辑 ✅ 手写 minify()
转译 把新语法 / TS / SCSS 变成浏览器能懂的老语法 ❌ 交给 Babel / esbuild
产物命名 文件名带内容哈希，配合强缓存做「永不失效 + 秒更新」 ❌ 交给 Vite

压缩不改变程序行为，只改变「传输体积」和「解析时间」—— 这也是它能被自动化到无脑执行的原因。

省下的部分几乎全是注释和缩进。体积按 UTF-8 字节算，一个中文注释字符占 3 字节 —— 所以中文注释多的项目，压缩收益会比纯英文项目更夸张，这也是「注释写清楚不心疼」的底气。

五、这套压缩碰不得的四个地方

  • ASI
  • 字符串
  • 正则
  • 模板字符串

所以真实工具不是用正则做压缩，而是先把代码解析成语法树（AST），再重新生成代码 —— 能区分「这是注释」和「这是字符串里的两个斜杠」。

六、既然能跑，为什么还要 Vite

能力 本章脚本 Vite
模块依赖分析 手写数组排顺序 读 import 自动排序
Tree Shaking 无：没用到的代码照样打包 删掉没被引用的导出
改代码后 手动重跑 node build.mjs 热更新，浏览器里直接生效
排错 压缩后行号全乱 sourcemap 映射回源码
缓存 文件名固定 → 改一次全量失效 内容哈希文件名 → 只失效改动的那一个

结论：几十行脚本能让你理解构建，但项目一旦上规模， 模块解析、Tree Shaking、sourcemap 这三件事就无法用脚本糊过去了 —— 该上 Vite 就上， 不必因为「手写显得硬核」而硬撑。
