一、配置到底要管什么

只有一类东西需要配置：同一份代码，在不同环境下必须取不同的值。 其余的都算常量，写死反而更清楚。

配置项 为什么各环境不同
API_BASE 开发连本地 localhost:3000，线上连正式域名
TIMEOUT 本地调试要等断点，线上要快速失败
DEBUG 开发要看日志，线上不能把内部信息打到控制台
LOG_LEVEL 预发要 info 方便排查，线上只留 error

二、一份配置，三种环境

差异集中在一张表里，业务代码只认 getConfig()， 再也不会出现「改接口地址要全仓库搜索替换」。

// config.js
var ENV_CONFIG = {
    development: {
        apiBase: 'http://localhost:3000/api',
        timeout: 10000,
        debug: true
    },
    production: {
        apiBase: 'https://api.example.com/api',
        timeout: 5000,
        debug: false
    }
};

// 业务代码里唯一的写法
var config = getConfig(resolveEnv(location.search, location.hostname));
fetch(config.apiBase + '/notes');

环境判断的优先级：URL 参数 ?env= → 域名 → 默认 development。 域名判断是线上真实做法：部署到哪个域名，就是哪个环境，不靠人记得改配置。

六、换成 Vite 项目后怎么写

真实项目不会手搓 resolveEnv，而是让构建工具在打包时把环境变量替换成字面量：

# .env.development
VITE_API_BASE=http://localhost:3000/api

# .env.production
VITE_API_BASE=https://api.example.com/api

// 业务代码
const apiBase = import.meta.env.VITE_API_BASE;
机制 说明
.env.[mode] 按模式加载：vite 用 development，vite build 用 production
VITE_ 前缀 只有这个前缀的变量会暴露给前端代码，其余仅构建时可读
import.meta.env.DEV 内置布尔值，判断开发/生产比自定义开关更可靠
值会被替换 打包时直接替换成字符串字面量，运行时没有 env 对象

所以「改环境变量」其实是「改构建参数 + 重新构建」。 想在运行时切换环境，还是得靠本页这种「域名 / URL 参数」的方式。
