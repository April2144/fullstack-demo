一个请求的完整流程

总览 请求流程 前后端职责 技术栈 环境搭建 项目结构

一、从输入网址到看到页面

下面这条链路是全栈开发的「主干道」。不管你写的是哪一层，最终都是在链路的某一环上工作。

浏览器发起请求
→
DNS域名 → IP
→
Nginx静态文件 / 转发
→
FastAPI业务逻辑
→
MySQL读写数据
→
响应JSON / HTML
→
渲染DOM 更新

二、每一环到底在干什么

环节 负责的事 出问题时的表现
浏览器 发请求、解析 HTML/CSS、执行 JS、渲染页面 页面白屏、控制台报错
DNS 把域名解析成服务器 IP 域名打不开，但直接用 IP 能开
Nginx 静态文件直接返回，接口请求转发给后端 404 / 502，静态资源 200 但接口挂了
FastAPI 校验参数、执行业务、组织响应 500 内部错误，或 422 参数校验失败
MySQL 持久化数据，按条件查询 接口变慢、数据不落库、连接数耗尽

三、同一条链路，两种走法

同样是「打开一个页面」，前后端分离与传统服务端渲染的链路不一样， 排查问题的第一步就是先搞清楚自己站在哪条链路上。

服务端渲染（SSR）

  • 浏览器请求页面 → Nginx → 后端查库 → 拼好 HTML 返回
  • 首屏快，SEO 友好
  • 每次切页都要重新请求整页

前后端分离

  • 浏览器先拿到静态 HTML/JS → JS 再 fetch 接口拿 JSON → 前端渲染
  • 切页不刷新，交互更顺
  • 首屏多一次请求，对 SEO 不友好（需要额外处理）

四、全栈开发的能力模型

全栈不是「每样都会一点」，而是能把一条链路自己走通。四层能力缺一层，链路就断。
