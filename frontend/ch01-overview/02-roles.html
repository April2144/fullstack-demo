前后端职责与协作方式

总览 请求流程 前后端职责 技术栈 环境搭建 项目结构

一、三层职责

划分职责只有一条原则：谁的数据谁负责，谁的能力谁实现。 前端不该直接连数据库，后端也不该拼 HTML。

层 该做的 不该做的
前端 页面结构、样式、交互、把接口数据渲染成界面 直接连数据库、信任前端传来的任何数据
后端 业务规则、参数校验、权限判断、组织响应 拼接页面 HTML、把数据库结构直接暴露给前端
数据库 存数据、保证一致性、按条件查询 写业务逻辑、做权限判断

二、接口就是双方签的合同

前后端各写各的，唯一的连接点是接口。接口定下来，两边才能并行开发。

请求（前端 → 后端）：

POST /api/notes
Content-Type: application/json

{
  "title": "第一条笔记",
  "body": "接口先定，再写实现"
}

响应（后端 → 前端）：

HTTP/1.1 201 Created
Content-Type: application/json

{
  "code": 201,
  "message": "创建成功",
  "data": { "id": 1, "title": "第一条笔记" }
}

约定三件事：路径和方法（谁在什么地址干什么）、 字段名与类型（别一边叫 title 一边叫 name）、 错误怎么表达（HTTP 状态码 + 业务错误码）。

三、数据流的方向

只有两个方向，记住这两条就不会绕晕：

读前端 → 后端 → 数据库 → 后端 → 前端
|
写前端提交 → 后端校验 → 数据库落库 → 返回结果

写操作必须校验：前端校验是为了体验（即时提示）， 后端校验是为了安全（前端校验可以被绕过）。两道都要有，不能只做一道。
